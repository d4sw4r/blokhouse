# OIDC Single Sign-On Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Sign in to Blokhouse with one generic OIDC provider (Keycloak, Entra ID), roles optionally from the directory, plus a deactivate switch for users and expiry rules for SSO users' API tokens.

**Architecture:** NextAuth v4's generic `oauth` provider (`wellKnown`, PKCE, state). All provisioning (create, link, role sync, refusals) happens in our own `signIn` callback, which writes the `Account` row itself; NextAuth's callback handler then finds that account and never creates users or throws `OAuthAccountNotLinked`. Configuration is parsed and validated once in `lib/oidc.js` and checked at server start in `instrumentation.ts`.

**Tech Stack:** Next.js 16, next-auth 4.24.15 + @next-auth/prisma-adapter, Prisma 7.10.1 (PostgreSQL), vitest, Playwright 1.63.0 (e2e), Keycloak (CI).

**Spec:** `docs/superpowers/specs/2026-11-26-oidc-sso-design.md`

## Global Constraints

- Env variables and defaults exactly as in the spec table: `OIDC_ISSUER`, `OIDC_CLIENT_ID`, `OIDC_CLIENT_SECRET`, `OIDC_NAME` (`Single sign-on`), `OIDC_SCOPES` (`openid email profile`), `OIDC_ROLE_CLAIM` (`groups`), `OIDC_ROLE_MAP`, `OIDC_DEFAULT_ROLE` (`READONLY`), `OIDC_TRUST_EMAIL` (`false`), `PASSWORD_LOGIN` (`true`), `SESSION_MAX_AGE` (`2592000`), `OIDC_TOKEN_MAX_DAYS` (`90`).
- Provider id is `oidc`; callback URL `<NEXTAUTH_URL>/api/auth/callback/oidc`.
- The `API` role is never granted through SSO (not allowed in the map or as default role); users with role `API` cannot sign in via SSO.
- Local admins (role ADMIN with a password) are never linked or changed by SSO.
- Linking removes the password and caps the user's tokens to `OIDC_TOKEN_MAX_DAYS`.
- Audit actor for SSO actions: the user; describe them with "via SSO".
- No new runtime dependencies. Playwright only in CI/e2e, version 1.63.0.
- Working branch `claude/oidc-sso`; commit after each task; CI must stay green (lint 0 errors, tsc, unit, integration, build, docker job).

## Review Focus

1. Role claim missing entirely from the token (Keycloak without groups mapper) while a role map is set → denied with the "no access" message, not a crash. Test in Task 1 (`mapRole` with `undefined`) and Task 3.
2. Email in different case than the existing user (`Alice@Corp.com` vs `alice@corp.com`) → treated as the same user (case-insensitive lookup), never a second account. Test in Task 3.
3. A user deactivated while an SSO sign-in is in progress, or a deactivated user whose `sub` is already linked → refused. Test in Task 3 (`linked + disabled`).
4. `OIDC_ROLE_MAP` with spaces or empty entries (`" cmdb-admins = ADMIN , ,"`) → parsed leniently; a typo in a role name → startup error naming the entry. Test in Task 1.
5. Token creation by an SSO user with `expiresInDays` given as a string (`"30"`) or omitted → string accepted when in range, omitted rejected with the max days in the message. Test in Task 4.

### Task 3: SSO sign-in (provider, provisioning, password login switch, session lifetime)

**Files:**
- Create: `lib/sso.js`
- Modify: `lib/authOptions.js`, `lib/users.js` (`signupEnabled` returns false when `!passwordLoginEnabled()`)
- Test: `__tests__/integration/sso.test.ts`

**Interfaces:**
- Consumes: `getOidcConfig`, `mapRole`, `passwordLoginEnabled`, `sessionMaxAge` (Task 1); `disabledAt` (Task 2); `createAuditLog` (`lib/audit.js`).
- Produces:
  - `handleOidcSignIn({ account, profile, config }) -> Promise<true | string>` in `lib/sso.js`: `true` to continue, or a redirect URL `/signin?error=<Code>`. Error codes (used by Task 5 for messages): `SsoNoEmail`, `SsoEmailNotVerified`, `SsoLocalAdmin`, `SsoNoAccess`, `SsoDisabled`, `SsoServiceAccount`.
  - In `authOptions`: provider `{ id: "oidc", name: config.name, type: "oauth", wellKnown: \`${issuer}/.well-known/openid-configuration\`, clientId, clientSecret, authorization: { params: { scope } }, idToken: true, checks: ["pkce","state"], profile(p) → { id: p.sub, name: p.name ?? p.preferred_username, email: p.email ?? null } }` only when `getOidcConfig()` is non-null; `callbacks.signIn` delegates to `handleOidcSignIn` for `account.provider === "oidc"` and returns `true` otherwise; `session.maxAge = sessionMaxAge()`; credentials `authorize` returns `null` when `!passwordLoginEnabled()`.
- Algorithm of `handleOidcSignIn` (the spec's "First login and account linking" and "Roles"; the order matters):
  1. Find `Account(provider "oidc", providerAccountId = sub)` with its user. If found: refuse `SsoDisabled` if deactivated, `SsoServiceAccount` if role API; if a role map is set, `role = mapRole(...)`, `null` → `SsoNoAccess`, otherwise update the role if it changed (audit); return `true`.
  2. `email = profile.email`; `fallback = profile.preferred_username` if it contains `@`. Neither → `SsoNoEmail`.
  3. If a role map is set, compute the role now; `null` → `SsoNoAccess` (before creating anything).
  4. Existing user by `profile.email`, case-insensitive (`mode: "insensitive"`). Only `profile.email` is used here, never the fallback.
     - deactivated → `SsoDisabled`; role API → `SsoServiceAccount`; role ADMIN with password → `SsoLocalAdmin`
     - not `email_verified === true` and not `config.trustEmail` → `SsoEmailNotVerified`
     - in one transaction: create the `Account` (fields from `account`: type, provider, providerAccountId, tokens as NextAuth stores them), set `password: null`, set the mapped role if a map is set, cap `ApiToken.expiresAt` (null or later than now + `tokenMaxDays`) to now + `tokenMaxDays`; audit "Linked SSO account"; return `true`.
  5. No existing user (lookup also by the fallback, case-insensitive; if a user with the fallback address exists → `SsoEmailNotVerified`, never link): create user `{ name, email: email ?? fallback, role: mapped ?? config.defaultRole }` and its `Account` in one transaction; audit "Created user via SSO"; return `true`.

- [ ] **Step 1: Write failing integration tests** `sso.test.ts`, calling `handleOidcSignIn` directly with fake `account` (`{ provider:"oidc", type:"oauth", providerAccountId:"sub-1", access_token:"x", id_token:"y", token_type:"bearer", expires_at: 1 }`) and `profile` and a config from `parseOidcConfig`:
  - new user, no map → `true`; user exists with role `READONLY`, an `Account` row, no password; audit row
  - new user, map `cmdb-admins=ADMIN`, `groups:["/cmdb-admins"]` → role ADMIN
  - map set, `groups` missing → `/signin?error=SsoNoAccess`, no user created
  - second sign-in with same `sub` and groups now `["cmdb-read"]` (map `cmdb-admins=ADMIN,cmdb-read=READONLY`) → role changed to READONLY, audit row
  - existing local USER `alice@corp.com` with password and a token without expiry, profile `Alice@Corp.com`, `email_verified:true` → linked (same user id, one user total), password null, token `expiresAt` ≈ now + 90 days
  - same without `email_verified` → `SsoEmailNotVerified`; with `OIDC_TRUST_EMAIL: "true"` → linked
  - existing ADMIN with password, verified email → `SsoLocalAdmin`, user unchanged
  - profile without `email`, `preferred_username: "bob@corp.com"`, no such user → created with that email
  - profile without `email`, `preferred_username` equal to an existing user's email → `SsoEmailNotVerified`, not linked
  - linked user deactivated → `SsoDisabled`; linked user with role API → `SsoServiceAccount`
  - no email and no usable `preferred_username` → `SsoNoEmail`
  - `signupEnabled()` with `ALLOW_SIGNUP=true` and `PASSWORD_LOGIN=false` → `false` (unit test in `__tests__/auth-signup.test.js`)
- [ ] **Step 2: Run** `npm run test:integration -- sso` — Expected: FAIL
- [ ] **Step 3: Implement `lib/sso.js`** per the algorithm, and wire `authOptions` as listed under Produces.
- [ ] **Step 4: Run** all integration and unit tests, `npm run lint`, `npx tsc --noEmit` — Expected: PASS
- [ ] **Step 5: Commit** `feat(auth): OIDC single sign-on`
